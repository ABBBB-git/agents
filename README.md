## 残課題

### 1. レビューエージェントへのレビュー観点の受け渡し

現状、レビューエージェントはレビュー観点を持たずに成果物を受け取っている。
汎用レビューエージェントである以上、レビュー観点は依頼元フェーズエージェントが提示すべき。

- [ ] 各フェーズエージェントがレビュー依頼時にレビュー観点をJSON内に含めて渡す設計

### 2. 設計フェーズの完了基準強化と差し戻しフロー

「設計完了」の定義が曖昧なままでは、次の実装フェーズで実装エージェントが独自判断するリスクがある。
設計完了の条件として少なくとも以下が必要：

- 再度設計に立ち戻らないレベルで詳細に設計されているか
- 不明瞭な仕様が残存していないか
- 実装エージェントが独自判断する余地が残存していないか

また、実装フェーズの禁止事項として「その場での再調査・再設計」を明示する必要がある。
再調査・再設計が必要になった場合は実装継続不可とし、オーケストレータに結果を返してオーケストレータが再設計を指示する差し戻しフローが必要。これは要求分析フェーズ等にも同様に適用できる。

- [ ] 設計フェーズの完了基準チェックリストの定義
- [ ] 実装フェーズへの「再調査・再設計禁止＋差し戻し」ルールの追加
- [ ] 各フェーズ共通の差し戻しフロー設計

### 3. 各フェーズ成果物のファイル出力

成果物をユーザーに提供するためには、成果物をファイルに残す必要がある。
そのためには以下の設計が必要：

- 成果物のファイルフォーマット（Markdown / JSON 等）の定義
- 成果物の出力先ディレクトリの指定ルール

- [ ] 成果物ファイルフォーマットの設計
- [ ] 出力先ディレクトリの指定ルールの設計
